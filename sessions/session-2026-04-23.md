## What I understood
- Nothing is permanently stored in the database until a COMMIT is executed. If something goes wrong before the commit, the transaction can be rolled back.
- When a transaction updates a record, the database locks that specific row. This means another transaction cannot update the same row until the first one finishes with a COMMIT or ROLLBACK.
- The main transaction principles are ACID: Atomicity means all or nothing; Consistency means the database moves from one valid state to another; Isolation means transactions do not interfere with each other; and Durability means committed data remains permanent.
- Savepoints allow us to roll back only part of a transaction instead of undoing everything.
- Functions return values and can be used inside a SELECT statement, which makes them useful for reusing logic in queries Procedures can receive inputs and may return outputs, but they are not used directly inside a SELECT.
